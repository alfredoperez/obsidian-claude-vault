# Surface: Vault Note

Obsidian knowledge notes, video notes, project notes, research notes.

Load `core-voice.md` first, then apply these overrides.

## Overrides (this surface only)

- **Em dashes are fine.** They're house style in vault notes. The shipping-content ban applies to
  articles, posts, and copy, not to notes.
- **Tables are fine, and often the right shape.** The no-tables rule exists because Medium can't
  render them. The vault renders them fine.
- **Voice is denser.** Notes are for a future reader who already has the context. Skip the hook and
  the rhetorical question. Lead with the finding.

## Structure

Notes follow the house shape:

1. **Frontmatter** — per the schema in `Vault-Guide.md` (tags, created, updated, and the type-specific
   fields)
2. **Intro abstract** — one paragraph: what this note holds and why it matters
3. **`## Key Learnings`** — bold lead-in per bullet, the claim first
4. **`## Details`** — the full explanation, sub-headed
5. **`## Sources`** — one `### Title — Channel (date)` per source, with bullets and a `[Watch](url)`
   or `[Read](url)` link
6. **`## Related Notes`** — `[[wikilinks]]` to neighbours

## Rules

- **Link liberally.** A `[[wikilink]]` to a note that doesn't exist yet is a feature, not an error.
  It marks the note worth writing.
- **Merge before you create.** Check whether an existing note already owns the topic. Enrich it and
  bump `updated:` rather than creating a near-duplicate.
- **Preserve the source's language in quotes**, then gloss in English if the note is in English.
- **Keep the claim, drop the throat-clearing.** No "In this note we will explore."

## Checklist

- [ ] Frontmatter matches the schema; `updated:` is current
- [ ] Key Learnings lead with the claim, in bold
- [ ] Sources section lists every source with a link
- [ ] Related Notes links out to neighbours
- [ ] Checked for an existing note that should have been enriched instead
